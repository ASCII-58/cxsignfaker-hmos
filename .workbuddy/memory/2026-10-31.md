## 二维码签到改为逐人扫码（commit 868510c 之后的新改动）

用户需求：多用户二维码签到时，每位用户实际调用一次扫码器获取新码值，不再串行复用同一 enc。

### 文档调研结论（scanBarcode.startScanForResult）
- 每次调用独立拉起系统扫码页，无多次调用限制；Promise resolve/reject 时扫码页已关闭，**串行 await 是唯一安全姿势**。
- 调用约束：「需要在页面和组件的生命周期内调用」；无需相机权限（系统页处理）。
- 错误码：401 参数错误 / 1000500001 内部错误 / **1000500002 用户取消**（reject 进 catch）。
- ScanResult.originalValue 为非可选 string；enableMultiMode 多码识别时选码不确定；相册识码仅单码；startScan 已废弃。

### 代码改动
1. `SignerPage.ets`：新增 `QrScanOutcome` 接口与 `scanQrEnc(uname)`（Promise 永不 reject；1000500002 归为 cancel；内容缺 enc 归为 format）。
2. `executeSignFlow`：QRCODE 时循环内逐人 `scanQrEnc` → ok 用新 enc；format 记 error 继续；cancel 补记剩余用户 `skipped` 后 break（修复了中断静默丢人）。`buildBaseParams` 移入循环内。
3. `handleSignAction` 二维码分支：删除内联扫码，直接 `executeSignFlow('', '')`。
4. `urlTools.ts`：`parseUrlParams` 改为只按第一个 `=` 分割，修复 Base64 型 enc 填充符被截断的坑。

## 新版扫码器（customScan + rescan）+ 设置开关（同日，commit b8b8f6b 之后）

- 新增 `Component/CustomScanPanel.ets`：XComponent(SURFACE) 渲染预览流，走 customScan.init → start(callback 版) → rescan 循环 → stop → release。需 `ohos.permission.CAMERA`（module.json5 + string.json 的 camera 已补）。
- **SDK 声明已核实**：`rescan(): void`（since 5.0.0/12），识别结果只从 **callback 版 start** 返回，Promise 版没有回传通道——这是选用 callback 版的硬约束。
- **连续扫码的重复计数陷阱（重要）**：识别成功后若立即 rescan，相机会对同一张码连续回调，会把同一帧计成下一位用户。改为「记录后延时 1800ms 自动恢复识别 + 提供『继续扫描』按钮立即恢复」。用时间窗去重是错误方案（窗口失效后同一码仍会被再次计入）。
- 设置项：`utils/settingsKeys.ets` 导出 `PREF_CUSTOM_SCAN_ENABLED = 'custom_scan_enabled'`，默认 false（旧版）。SettingsComponent 新增「签到 / 新版扫码器」Toggle；SignerPage.initPageData 读偏好，`useCustomScanner` 决定 executeSignFlow 走「先收满 N 个 enc 再逐个签到」还是「循环内逐人拉起系统扫码页」。
- 面板用 `bindContentCover` 承载，`onDisappear` 统一 resolve `collectEncs`，避免 Promise 永久挂起。
- 编译：BUILD SUCCESSFUL。**未真机验证**：bindContentCover 模态层内 XComponent 相机流渲染、rescan 实际回调时序、相机权限弹窗与面板的交互，均需真机确认。
