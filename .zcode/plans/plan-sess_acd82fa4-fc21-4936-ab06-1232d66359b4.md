## 目标

1. **多用户验证码弹窗复用**：整轮签到期间弹窗保持打开，换用户时原地刷新内容并带淡出/淡入切换动画，全部用户签到结束后统一关闭（当前：每个用户"关闭→重开"一次）。
2. **模型识别状态展示**：识别过程中在弹窗内显示带动画的分阶段状态文案（加载模型→识别中→提交校验→成功/失败），失败提示从 toast 改为弹窗内红字（当前：全程裸转圈，成功静默）。
3. **Debug 页本地演示**：DebugPage 新增"验证码弹窗演示"卡片，可打开演示弹窗、点"模拟下一位用户"观察切换动画与状态文案（全本地模拟，不访问网络，成功/失败按次数交替演示）。

## 关键机制（现状结论）

- `SignerPage.ets:333/338/470` 三条路径都无条件 `captchaSheetShow = false`，`:946` 又对下一用户重新置 true → 重开动画。
- `Captcha.ets` 的 `captchaUser` 是普通成员（:31），子组件重初始化完全依赖弹窗重开触发 `aboutToAppear`；`modelTried`（:54）等一次性状态也靠重开重置。
- `tryModelCheck()`（:135-172）整个跑在 `isLoading` 窗口内，build() 的 isLoading 分支（:235-243）只渲染裸 `LoadingProgress`。

### 1. `entry/src/main/ets/pages/SignerPage.ets`

- 新增 `@State captchaSession: number = 0`（:58 附近）。
- `requestCaptcha`（:935-950）：设置 `captchaUser` 后 `this.captchaSession++`；`captchaSheetShow = true` 保留（已开时是 no-op，不会重开）。
- `CaptchaSheetBuilder`（:327-344）：给 `CaptchaComponent` 传 `captchaSession: this.captchaSession`；`onValidated`/`onSkip` **删掉 `captchaSheetShow = false`**，只 resolve + 清 resolver。
- `executeSignFlow`（:797-825）：循环结束后、`showSignResult` 之前统一收口 `captchaSheetShow = false; captchaResolver = null`（qrcodeExpired break 也走这里；先关弹层再弹结果对话框）。

### 2. `entry/src/main/ets/Component/Captcha.ets`

- 新增：`@Prop @Watch('onCaptchaSessionChanged') captchaSession: number = 0`、`demoMode?: boolean = false`、`@State autoStatus/resultHint/resultOk/contentOpacity`。
- `onCaptchaSessionChanged()`：重置 `modelTried=false` → 重新读 Beta 开关 → `refresh()`（弹层跨用户复用时的重初始化路径；首次挂载走 `aboutToAppear` 不触发 watch）。

- `tryModelCheck()`（:135-172）各阶段设置文案：`正在加载本地模型…` / `正在获取验证码图片…` / `模型识别中…` / `识别位置 x=N，正在提交校验…`；成功 `resultHint='校验通过'`（绿色）后 `finish()`；滑块**不**自动移动（按你的选择）。
- `notifyModelFallback()`（:174-176）：toast 改为弹窗内红字 `resultHint='模型自动验证失败，请手动完成验证'`（用现有 `$r('app.color.unsignable')`）。
- `build()`：
  - 图片区分支改为 `isLoading && !info.token` → 转圈 / `errMsg` → 报错 / 其余 → 图片（识别阶段图片保持可见，与状态行共存）。
  - 图片区与 Slider 之间插入状态行：`autoStatus` 非空 → Row(迷你 LoadingProgress 18×18 + 文案)；否则 `resultHint` 非空 → 彩色文案（成功 `$r('app.color.signed')` / 失败 `$r('app.color.unsignable')`，两者已被 SettingsComponent 模型测试结果使用，存在则复用、缺失则补 base+dark 两套）。出现/消失用 `TransitionEffect.OPACITY…animation({duration:200})`。
  - 内容区（标题+图片区+状态行）包一层 `opacity(contentOpacity).animation()` 实现换用户切换动画。
- **demoMode 分支**（全本地）：`refresh()` 走 `demoFlow()`：模拟拉取 500ms → 占位验证码图 → 依次播放状态文案（正在自动校验/加载模型/识别中，各 500-800ms）→ `captchaSession` 奇数=校验通过并回调 `onValidated('demo-validate')`，偶数=失败红字回退；手动拖滑块在 demo 下也模拟"提交校验→通过"；不调用任何真实 API / prefs。

## 边界与风险

- `@Watch` 不在首挂载触发 → 首个用户仍走 `aboutToAppear`，行为不变；弹窗关闭后重开时子组件重建，同样走 `aboutToAppear`。
- 用户在模型识别中点"跳过该用户"：resolver 已消费，后续识别完成的 `finish()` 回调落空（no-op），无害。
- 用户在模型识别中手动关掉弹层且流程结束：子组件卸载后的迟到状态写入为无害 no-op。
- `demoMode` 必须短路所有网络/prefs 调用（getCaptchaPhotos/checkPosition/saveMemory/memory pref）。
